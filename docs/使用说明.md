# win-ssh-setup 使用说明

Windows SSH 免密登录一键配置工具：在两台电脑上各运行一次，自动完成密钥生成、公钥部署、权限修复、sshd 配置适配与**配置体检**，**全程只需在客户端输入一个配对码**（局域网 6 位一次性码；异地场景可用 8 位持久码）。适用于 Windows 11 空密码 / 微软在线账户场景下 SSH 拒绝登录的问题（背景见《手动操作流程.md》）。

## 环境要求

- 两台 Windows 10 / 11 电脑，处于同一局域网（本机自连模式只需一台）
- Node.js ≥ 18 —— 双击 `run.cmd` 时未安装会自动通过 winget 安装 LTS 版
- 服务器端需要管理员权限（脚本自动弹出 UAC）
- 服务器端未安装 OpenSSH Server 时自动安装：
  - 优先 `winget install Microsoft.OpenSSH.Preview`（即 `winget install "openssh preview"`）
  - 失败自动回退系统内置 `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`

## 运行模式

```
 [1] 服务器端  —— 本机作为被连接的 SSH 服务器（需要管理员）
 [2] 客户端    —— 本机发起连接，把本机公钥部署到对方
 [3] 本机自连  —— 生成密钥并部署到本机（ssh localhost）
 [4] 密钥管理  —— 客户端/服务端密钥查看、体检、删除、清空、备份
```

## 快速开始

### 第一步：服务器端（被连接的电脑）

1. 双击 `run.cmd`，选择 `[1] 服务器端`，确认 UAC 提权
2. 屏幕显示：

```
══ 等待客户端连接 ══
  本机地址 : 192.168.1.10   端口 : 22887
  配对码   : 583 214   ← 请在客户端输入这串数字
  快捷键   : [p] 生成持久配对码（异地连接，不轮换）  [d] 销毁持久码  [q] 退出
```

3. 保持窗口开着，等待客户端连接（异地场景先按 `p` 激活持久配对码，见下文「异地配对」）

> 防火墙自动处理：服务器启动时自动添加临时放行规则（TCP 22887），退出时自动删除。若本机防火墙策略由组策略管控、忽略本地规则（症状：规则在却连不上，ICMP 等其他端口正常），工具会检测到并临时开启"本地规则合并"使规则生效，退出时自动还原原策略；域管控机器若被组策略刷新覆盖，请用本地安全策略（`secpol.msc`）放行。客户端可先用 `Test-NetConnection 服务器IP -Port 22887` 验证配对端口可达。

### 第二步：客户端（发起连接的电脑）

1. 双击 `run.cmd`，选择 `[2] 客户端`
2. 脚本自动搜索局域网内等待配对的服务器；找到后列出让您选择，**未找到或没来得及启动服务器时可选 `[r]` 重新扫描**（也可 `[m]` 手动输 IP、`[0]` 返回菜单）
3. 若本机保存过该服务器的部署记录（首次配对没有），会自动做一次**免密预检**：已能免密登录则提示"已可免密连接，跳过重复部署"，**不要求配对码、不重新部署**（服务器端 sshd 不会被重启打扰）；预检未通过则继续正常配对流程
4. 输入服务器屏幕上的 **配对码**（局域网临时码为 6 位，一次性使用，配对成功后服务器自动更新为新码；持久码为 8 位）
5. 剩余全部自动，且**三层验证逐级给出状态**：

```
① 自动部署（服务器端执行 6 步，步骤实时回传）
② 配置体检（服务器端 11 项纯配置检查，无连接，结果实时回传）
③ 可选实测（询问后发起一次真实 ssh 连接做最终确认）
```

6. 若检测到本机旧公钥残留（更换过密钥的场景），会列出并询问是否一键清理

完成后即可用 `ssh 用户名@服务器IP` 直接登录，无需任何密码。

> 部署成功后，客户端会在 `~\.ssh\win-ssh-setup-servers.json` 保存一份部署记录（服务器 IP、登录用户名、公钥指纹、部署时间）。下次再选择同一台服务器时据此自动免密预检——已可连接就不再重复部署；记录文件可随时删除，删除后恢复"每次都走配对"的行为。

### 本机自连

同一台电脑既当客户端又当服务器（`ssh localhost`）：选择 `[3] 本机自连`，同样走"部署 → 体检 → 可选实测"流程。

### 异地配对（持久配对码）

两台电脑不在同一局域网时（例如出门在外连回家里的电脑），用**持久配对码**完成配对：

1. **出发前**：在服务器端电脑选 `[1] 服务器端`，等待界面按 **`p`** 激活持久配对码——8 位数字（如 `3705 7484`），**不轮换、可重复使用**，把码抄下来带走
2. **保持在线**：出走期间服务器端电脑需保持开机联网、窗口不关，并建议暂时关闭睡眠（设置 → 系统 → 电源）；跨网访问需保证 22887 端口可达——**优先走 VPN/Tailscale 等隧道**（配对通道是明文 HTTP，隧道内更安全），或在路由器上做端口映射
3. **异地连接**：在远端电脑选 `[2] 客户端`，UDP 自动发现跨网段不可用属预期行为，选 **`[m]` 手动输 IP**（VPN 内网 IP、公网 IP 或 `IP:端口`），输入持久配对码，剩余流程与局域网完全一致
4. **完成设置后销毁**：配对成功后客户端会询问"是否销毁服务器上的持久配对码"，选 `y` 即远程销毁（服务器回到临时码模式）；也可回到服务器端按 **`d`** 销毁。**关闭服务器端进程（窗口/`[q]`/Ctrl+C）时持久码自动失效**

安全说明：持久码在激活期间持续有效，请勿在公共场合泄露；配对码连续输错 5 次会锁定 30 分钟（防爆破）；远程销毁凭配对时签发的会话令牌（10 分钟内有效），超过时效可重新配对一次再销毁。

## 密钥管理（[4]，两端都可以是服务端）

哪台机器运行就管理**那台机器**的密钥，界面区分两个分区：

```
── 客户端密钥（本机身份，用于连别人）──
  K1  ED25519  SHA256:AbCd...  alis@DESKTOP-A

── 服务端授权公钥（部署到本机的，本机作为服务端）──
  [1] (用户)   ED25519  SHA256:Yyy...  bob@DESKTOP-B
  [2] (管理员) RSA      SHA256:Zzz...  old-laptop
```

| 操作 | 说明 |
|---|---|
| `[c]` 体检 | 对本机配置与已部署公钥做 11 项配置体检（无连接），FAIL 项支持一键修复 |
| `[d]` 删除 | 删除指定服务端授权公钥（可多选），删前自动备份 |
| `[k]` 清空 | 清空指定授权文件，需输入 `YES` 二次确认 |
| `[b]` 备份 | 备份授权文件与客户端密钥对 |
| `[g]` 重新生成客户端密钥 | 旧密钥自动备份；旧公钥在服务器上的残留可在下次配对时自动清理 |

安全设计：删除/清空即时生效（authorized_keys 每次认证时读取，**无需重启 sshd**）；注释行/无法识别的行永不触碰；管理员授权文件修改后自动重新收紧 ACL；管理操作需要管理员权限时自动弹 UAC。

## 配置体检包含什么

在服务器端本地检查（不发起任何连接），判断"按当前配置，免密登录是否应可生效"：

1. 公钥位置与配置一致性（管理员组用户时判定 Match 规则指向的实际读取文件）
2. 管理员授权文件 ACL（SDDL 解析，仅 Administrators/SYSTEM、继承禁用——过宽时 sshd 会静默拒读）
3. 用户文件与 .ssh 权限
4. `PubkeyAuthentication` 未被关闭
5. `AllowUsers / DenyUsers / AllowGroups / DenyGroups` 限制
6. `sshd -t` 配置语法
7. sshd 服务状态
8. 主机密钥存在
9. 账户启用状态
10. 端口与防火墙配置
11. 微软账户 Match 规则风险告警

> 边界说明：配置体检是必要条件验证；客户端是否持有匹配私钥、网络是否实时可达，只有"实测连接"能证明。

## 脚本部署做了什么（服务器端六步，全部幂等）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 追加公钥到 `C:\Users\<用户>\.ssh\authorized_keys` | 已存在则跳过 |
| 2 | 追加公钥到 `C:\ProgramData\ssh\administrators_authorized_keys` | 仅管理员组用户 |
| 3 | `icacls` 收紧该文件 ACL | 仅 `Administrators`（SID `*S-1-5-32-544`）与 `SYSTEM`（`*S-1-5-18`）可访问 |
| 4 | 备份并修补 `sshd_config` | 注释 `Match Group administrators` 块，绕开微软账户 SID 解析问题 |
| 5 | `sshd -t` 配置校验 | 校验失败自动回滚备份，不重启服务 |
| 6 | 重启 sshd 服务 | 启动类型设为 Automatic |

## 网络与端口

- TCP **22887**：配对通道（部署、体检结果回传、旧 key 清理、持久码销毁共用），服务器端自动添加临时防火墙规则 `win-ssh-setup-pair-tmp`，退出自动删除
- UDP **22888**：局域网发现信标（每 2 秒广播一次）
- **临时配对码**（默认）：6 位数字，一次性使用，每次配对成功后自动轮换为新码（服务器屏幕即时显示），旧码立即作废；"清理旧公钥"等后续操作凭配对时签发的会话令牌（10 分钟有效）鉴权
- **临时码定时轮换**：未使用时也每 5 分钟自动轮换（间隔可在 `src\config.js` 调整），定时轮换不影响已签发的会话令牌
- **持久配对码**：8 位数字，服务器端按 `p` 手动激活，不轮换、可重复使用，直至手动销毁（服务器端按 `d` 或客户端远程销毁）或进程退出；详见「异地配对（持久配对码）」章节
- **防爆破锁定**：配对码连续输错 5 次（`PAIR_MAX_CODE_FAILS`）锁定 30 分钟（`PAIR_LOCKOUT_MS`，均可在 `src\config.js` 调整），锁定期间所有配对请求一律拒绝；配对成功即重新计数
- 公钥格式、指纹格式服务端二次校验（配对码比对使用 `timingSafeEqual` 防时序侧信道）

## 回滚方法

- `sshd_config`：用备份文件覆盖回去（`C:\ProgramData\ssh\sshd_config.bak.<时间戳>`），然后 `Restart-Service sshd`
- 删除/恢复公钥：编辑 `C:\Users\<用户>\.ssh\authorized_keys` 与 `C:\ProgramData\ssh\administrators_authorized_keys`，或直接在 `[4] 密钥管理` 中操作（所有修改前都有 `.bak.<时间戳>` 自动备份）
- 客户端密钥：`[g]` 重新生成前旧密钥自动备份
- 卸载 OpenSSH：`winget uninstall Microsoft.OpenSSH.Preview`

## 常见问题

- **客户端搜不到服务器**：两机不在同一网段、路由器开启了 AP 隔离、或广播被防火墙拦截。改用服务器菜单里的手动 IP 方式（客户端选 `[m]` 手动输入）。
- **异地连不回家里电脑**：持久配对码只解决"认证"，网络必须先通——优先 VPN/Tailscale，其次路由器端口映射；客户端先走 `[m]` 手动输 IP，TCP 预检通过再输码。
- **提示"配对码连续错误次数过多，已锁定"**：连续输错 5 次触发 30 分钟防爆破锁定，等锁定结束再试；期间服务器端按 `p` 重发持久码**不会**解除锁定（防止绕过），只有一次成功配对才重新计数。
- **VPN / 虚拟网段场景**（两机处于不同 VPN 网段，如 10.6.0.x 与 10.51.0.x）：UDP 广播跨不过隧道，自动发现不可达属**预期行为**，直接手输服务器屏幕上的 IP 即可（配对走 TCP 通道）。若出现"已受理但迟迟无结果流"，可能是 VPN/安全软件拦截了响应：部署是幂等操作，可等超时提示后重试，或在服务器端 `[4] 密钥管理` 直接确认部署结果。
- **快速诊断响应方向**：在客户端执行（配对码以服务器屏幕当前显示为准，一次性码）：
  `curl.exe -X POST http://服务器IP:22887/pair -H "X-Pair-Code: 当前配对码" -H "Content-Type: application/json" -d "{\"pubkey\":\"diag\",\"clientHostname\":\"diag\"}"`
  能收到 JSON 响应（哪怕是"公钥格式不正确"）说明通道正常；长时间挂起则说明响应被网络路径拦截。
- **体检有 FAIL 但实测失败原因不明**：看体检项的修复建议；FAIL 项多数可 `[c]` 体检后一键修复。
- **更换了客户端密钥**：重新运行 `[2]` 客户端配对即可——新 key 自动部署，旧 key 会被检测并询问清理；也可在服务器端 `[4]` 密钥管理中手动删除。
- **提示端口 22887 被占用**：关闭占用程序后重试。
- **winget 安装失败**：自动回退系统可选功能安装；都失败时按提示手动安装后再运行。
- **部署第 6 步失败"sshd 服务未注册"**：机器处于"半安装"状态（sshd.exe 存在但 Windows 服务缺失，常见于 MSI 安装不完整或系统升级后服务丢失）。重新在服务器模式运行本工具，会检测到并询问自动注册服务（服务首次启动自动生成主机密钥）；也可手动修复：`winget install --id Microsoft.OpenSSH.Preview -e` 重装补建服务。
- **中文乱码**：`run.cmd` 已执行 `chcp 65001`；若仍乱码请使用 Windows Terminal。
