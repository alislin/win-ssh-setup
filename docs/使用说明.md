# win-ssh-setup 使用说明

Windows SSH 免密登录一键配置工具：在两台电脑上各运行一次，自动完成密钥生成、公钥部署、权限修复、sshd 配置适配与**配置体检**，**全程只需在客户端输入一个 6 位配对码**。适用于 Windows 11 空密码 / 微软在线账户场景下 SSH 拒绝登录的问题（背景见《手动操作流程.md》）。

## 环境要求

- 两台 Windows 10 / 11 电脑，处于同一局域网（本机自连模式只需一台）
- Node.js ≥ 18 —— 双击 `run.cmd` 时未安装会自动通过 winget 安装 LTS 版
- 服务器端需要管理员权限（脚本自动弹出 UAC）
- 服务器端未安装 OpenSSH Server 时自动安装：
  - 优先 `winget install Microsoft.OpenSSH.Preview`（即 `winget install "openssh preview"`）
  - 失败自动回退系统内置 `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`

## 运行模式

```
 [1] 服务器端  —— 本机作为被连接的 SSH 服务器（需要管理员）
 [2] 客户端    —— 本机发起连接，把本机公钥部署到对方
 [3] 本机自连  —— 生成密钥并部署到本机（ssh localhost）
 [4] 密钥管理  —— 客户端/服务端密钥查看、体检、删除、清空、备份
```

## 快速开始

### 第一步：服务器端（被连接的电脑）

1. 双击 `run.cmd`，选择 `[1] 服务器端`，确认 UAC 提权
2. 屏幕显示：

```
══ 等待客户端连接 ══
  本机地址 : 192.168.1.10   端口 : 22887
  配对码   : 583 214   ← 请在客户端输入这串数字
```

3. 保持窗口开着，等待客户端连接

### 第二步：客户端（发起连接的电脑）

1. 双击 `run.cmd`，选择 `[2] 客户端`
2. 脚本自动搜索局域网内等待配对的服务器（也可手动输入 IP）
3. 输入服务器屏幕上的 **6 位配对码**
4. 剩余全部自动，且**三层验证逐级给出状态**：

```
① 自动部署（服务器端执行 6 步，步骤实时回传）
② 配置体检（服务器端 11 项纯配置检查，无连接，结果实时回传）
③ 可选实测（询问后发起一次真实 ssh 连接做最终确认）
```

5. 若检测到本机旧公钥残留（更换过密钥的场景），会列出并询问是否一键清理

完成后即可用 `ssh 用户名@服务器IP` 直接登录，无需任何密码。

### 本机自连

同一台电脑既当客户端又当服务器（`ssh localhost`）：选择 `[3] 本机自连`，同样走"部署 → 体检 → 可选实测"流程。

## 密钥管理（[4]，两端都可以是服务端）

哪台机器运行就管理**那台机器**的密钥，界面区分两个分区：

```
── 客户端密钥（本机身份，用于连别人）──
  K1  ED25519  SHA256:AbCd...  alis@DESKTOP-A

── 服务端授权公钥（部署到本机的，本机作为服务端）──
  [1] (用户)   ED25519  SHA256:Yyy...  bob@DESKTOP-B
  [2] (管理员) RSA      SHA256:Zzz...  old-laptop
```

| 操作 | 说明 |
|---|---|
| `[c]` 体检 | 对本机配置与已部署公钥做 11 项配置体检（无连接），FAIL 项支持一键修复 |
| `[d]` 删除 | 删除指定服务端授权公钥（可多选），删前自动备份 |
| `[k]` 清空 | 清空指定授权文件，需输入 `YES` 二次确认 |
| `[b]` 备份 | 备份授权文件与客户端密钥对 |
| `[g]` 重新生成客户端密钥 | 旧密钥自动备份；旧公钥在服务器上的残留可在下次配对时自动清理 |

安全设计：删除/清空即时生效（authorized_keys 每次认证时读取，**无需重启 sshd**）；注释行/无法识别的行永不触碰；管理员授权文件修改后自动重新收紧 ACL；管理操作需要管理员权限时自动弹 UAC。

## 配置体检包含什么

在服务器端本地检查（不发起任何连接），判断"按当前配置，免密登录是否应可生效"：

1. 公钥位置与配置一致性（管理员组用户时判定 Match 规则指向的实际读取文件）
2. 管理员授权文件 ACL（SDDL 解析，仅 Administrators/SYSTEM、继承禁用——过宽时 sshd 会静默拒读）
3. 用户文件与 .ssh 权限
4. `PubkeyAuthentication` 未被关闭
5. `AllowUsers / DenyUsers / AllowGroups / DenyGroups` 限制
6. `sshd -t` 配置语法
7. sshd 服务状态
8. 主机密钥存在
9. 账户启用状态
10. 端口与防火墙配置
11. 微软账户 Match 规则风险告警

> 边界说明：配置体检是必要条件验证；客户端是否持有匹配私钥、网络是否实时可达，只有"实测连接"能证明。

## 脚本部署做了什么（服务器端六步，全部幂等）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 追加公钥到 `C:\Users\<用户>\.ssh\authorized_keys` | 已存在则跳过 |
| 2 | 追加公钥到 `C:\ProgramData\ssh\administrators_authorized_keys` | 仅管理员组用户 |
| 3 | `icacls` 收紧该文件 ACL | 仅 `Administrators`（SID `*S-1-5-32-544`）与 `SYSTEM`（`*S-1-5-18`）可访问 |
| 4 | 备份并修补 `sshd_config` | 注释 `Match Group administrators` 块，绕开微软账户 SID 解析问题 |
| 5 | `sshd -t` 配置校验 | 校验失败自动回滚备份，不重启服务 |
| 6 | 重启 sshd 服务 | 启动类型设为 Automatic |

## 网络与端口

- TCP **22887**：配对通道（部署、体检结果回传、旧 key 清理共用），服务器端自动添加临时防火墙规则 `win-ssh-setup-pair-tmp`，退出自动删除
- UDP **22888**：局域网发现信标（每 2 秒广播一次）
- 配对码用于防止连错机器；公钥格式、指纹格式服务端二次校验

## 回滚方法

- `sshd_config`：用备份文件覆盖回去（`C:\ProgramData\ssh\sshd_config.bak.<时间戳>`），然后 `Restart-Service sshd`
- 删除/恢复公钥：编辑 `C:\Users\<用户>\.ssh\authorized_keys` 与 `C:\ProgramData\ssh\administrators_authorized_keys`，或直接在 `[4] 密钥管理` 中操作（所有修改前都有 `.bak.<时间戳>` 自动备份）
- 客户端密钥：`[g]` 重新生成前旧密钥自动备份
- 卸载 OpenSSH：`winget uninstall Microsoft.OpenSSH.Preview`

## 常见问题

- **客户端搜不到服务器**：两机不在同一网段、路由器开启了 AP 隔离、或广播被防火墙拦截。改用手动 IP 方式（客户端选 `[m]` 手动输入）。
- **体检有 FAIL 但实测失败原因不明**：看体检项的修复建议；FAIL 项多数可 `[c]` 体检后一键修复。
- **更换了客户端密钥**：重新运行 `[2]` 客户端配对即可——新 key 自动部署，旧 key 会被检测并询问清理；也可在服务器端 `[4]` 密钥管理中手动删除。
- **提示端口 22887 被占用**：关闭占用程序后重试。
- **winget 安装失败**：自动回退系统可选功能安装；都失败时按提示手动安装后再运行。
- **中文乱码**：`run.cmd` 已执行 `chcp 65001`；若仍乱码请使用 Windows Terminal。
