# win-ssh-setup 技术方案

将 `docs/手动操作流程.md` 中的手工 SSH 免密登录配置流程，封装为 Node.js 脚本工具，支持**两机对联配对**，在客户端一侧完成全部操作。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| OpenSSH Server 安装 | `winget install "openssh preview"`（包 ID：`Microsoft.OpenSSH.Preview`，MSI，配置路径与系统内置版一致 `C:\ProgramData\ssh`）；失败时回退 `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0` |
| 使用模式 | 两机对联：两端都启动脚本并建立连接，用户只在客户端一侧操作；另保留"本机自连"模式 |
| 技术栈 | Node.js ≥ 18，**零第三方依赖**（仅内置模块 http/dgram/child_process/fs/readline/crypto） |
| 服务器发现 | UDP 广播自动发现 + 手动输入 IP 兜底 |
| 端口 | 固定：TCP **22887**（HTTP 配对）、UDP **22888**（发现信标） |
| 日志 | 每一步彩色分步日志，客户端与服务器两端同步展示 |

## 用户交互设计

### 入口

`run.cmd` 双击启动 → 检测 `node`（缺失时自动 `winget install OpenJS.NodeJS.LTS`）→ `chcp 65001` → `node src\cli.js`。

### 角色菜单

```
════════════════════════════════════════════
   Windows SSH 免密登录一键配置 v1.0
════════════════════════════════════════════
 [1] 服务器端（我是被连接的一方）
 [2] 客户端（我是发起连接的一方）
 [3] 本机自连（生成密钥并部署到本机，ssh localhost）
 [0] 退出
```

### 服务器端流程（唯一需要 UAC 提权的一端）

1. 环境自检：管理员权限 / 当前用户 / 是否管理员组 / OpenSSH Server 是否安装
2. 非管理员 → 自动 UAC 提权重启自身
3. 未装 OpenSSH Server → 询问后 winget 安装（实时进度日志），并善后：服务启动类型设 Automatic、防火墙 22 端口规则
4. 添加**临时**防火墙规则（限 TCP 22887），退出时删除
5. 启动 HTTP :22887 监听 + UDP :22888 信标，屏幕显示本机地址、端口、6 位配对码
6. 收到配对请求 → 校验配对码 → 执行 6 步部署管线（逐步日志）→ 回传结果 → 完成面板（含 sshd_config 备份路径，用于回滚）

### 客户端流程（无需提权）

1. 环境自检：ssh 客户端可用、密钥对是否存在（存在则询问复用；不存在自动生成 ed25519 空口令密钥）
2. UDP 发现等待中的服务器（列出 主机名/IP），5 秒超时后提供手动输 IP
3. 唯一必要输入：服务器屏幕上的 **6 位配对码**
4. 发送公钥 → 实时展示服务器回传的每步执行日志
5. 自动验证：`ssh -o BatchMode=yes user@host exit`
6. 成功面板：打印 `ssh user@host` 测试命令

### 本机自连流程

跳过网络：keygen → 本地部署 → 验证 `ssh localhost`。

## 技术方案

### 目录结构

```
win-ssh-setup/
├── run.cmd            # 启动器：检测 node → node src\cli.js
├── src/
│   ├── cli.js         # 入口：角色菜单
│   ├── config.js      # 端口/魔数/版本常量
│   ├── log.js         # 统一彩色分步日志 [HH:mm:ss] [TAG] message
│   ├── exec.js        # 子进程封装（run / runPS / pump / resolveTool）
│   ├── env.js         # 环境自检（管理员、用户组、openssh、密钥对）
│   ├── install.js     # winget 装 OpenSSH + 服务/防火墙善后（capability 回退）
│   ├── elevate.js     # UAC 提权重启自身（powershell Start-Process -Verb RunAs）
│   ├── keygen.js      # ssh-keygen 封装
│   ├── pair-server.js # HTTP :22887 + UDP :22888 信标 + 配对码
│   ├── pair-client.js # UDP 发现 / 手动 IP + 发送公钥 + 接收实时日志
│   ├── deploy.js      # 6 步部署管线（仅服务器端执行，幂等）
│   └── verify.js      # BatchMode 试连验证
└── docs/
```

### 配对协议（v1）

- 请求：`POST http://<server>:22887/pair`，Header `X-Pair-Code: 583214`，Body JSON `{ pubkey, clientHostname }`
- 响应：NDJSON 流，每行一个 JSON：`{"type":"step","name":...,"status":"OK"|"SKIP"|"FAIL","detail":...}`，最后一行 `{"type":"done","ok":...,"serverUser":...}`
- UDP 信标（22888）：JSON `{ magic: "WIN-SSH-SETUP-BEACON", hostname, httpPort }`，客户端按 magic 过滤
- 安全校验：配对码比对 + 公钥格式正则 `^(ssh-ed25519|ssh-rsa|ecdsa-sha2-\S+|sk-\S+)\s+[A-Za-z0-9+/=]+`

### 部署管线（deploy.js，全部幂等）

1. 追加公钥到 `%USERPROFILE%\.ssh\authorized_keys`（目录/文件自动创建，追加前查重）
2. 当前用户属管理员组 → 同时追加到 `C:\ProgramData\ssh\administrators_authorized_keys`
3. `icacls administrators_authorized_keys /inheritance:r /grant *S-1-5-32-544:F /grant *S-1-5-18:F`（用 SID 免受系统语言影响）
4. 备份 `sshd_config` → `sshd_config.bak.<yyyyMMdd-HHmmss>`，注释 `Match Group administrators` 块及其块内的 `AuthorizedKeysFile __PROGRAMDATA__/ssh/administrators_authorized_keys` 行（已注释则跳过）
5. `sshd -t` 校验配置（自动定位 sshd.exe：`C:\Program Files\OpenSSH\` 或 `C:\Windows\System32\OpenSSH\`）；**校验失败则回滚备份、不重启服务**
6. `Restart-Service sshd`，启动类型设为 Automatic

### 其他技术要点

- 特权命令统一通过 `powershell.exe -Command` 子进程执行（服务器端进程本身已提权）
- 中文输出：`run.cmd` 中 `chcp 65001`，源码文件 UTF-8
- 日志状态标记：`[OK]` 绿 / `[SKIP]` 黄 / `[FAIL]` 红 + 修复建议
- 退出码：0 成功 / 非 0 失败

## 实现步骤

1. 骨架：run.cmd + cli.js 菜单 + env.js + log.js
2. keygen.js（生成/复用密钥）
3. deploy.js 六步管线（先支持本机自连路径，尽早可测）
4. install.js（winget 安装 + capability 回退 + 服务/防火墙善后）
5. elevate.js（UAC 提权）
6. pair-server.js / pair-client.js（UDP 发现 + HTTP 配对 + 配对码）
7. verify.js（BatchMode 自动验证）
8. 本机自连模式串联
9. docs/使用说明.md + README

## 测试要点

- 管理员/微软在线账户的服务器端（Match Group 规则触发场景）
- 服务器未装 OpenSSH Server → 自动安装路径
- 重复运行幂等性（公钥不重复、不重复备份、已注释行跳过）
- 错误配对码被拒绝；防火墙拦截 UDP 时手动 IP 兜底可用
- sshd -t 校验失败时的回滚
- 本机自连模式
- 旧版 conhost 与 Windows Terminal 的中文/颜色渲染

## 风险与对策

| 风险 | 对策 |
|---|---|
| 目标机器无 Node | run.cmd 自动 winget 装 LTS；无网络时提示手动安装 |
| winget 下载 OpenSSH 失败（无外网） | 回退 Add-WindowsCapability（走 Windows Update） |
| 杀软/防火墙拦 UDP 广播 | 手动输 IP 兜底 |
| 中文乱码 | chcp 65001 + UTF-8 文件 |
| 误改 sshd_config | 先备份 + sshd -t 校验 + 失败自动回滚，不重启服务 |

## v1.1 增补：密钥管理 / 配置体检 / 换 key 清理

### 已确认决策

| 决策点 | 结论 |
|---|---|
| 密钥管理范围 | 仅本机管理（两端都可以是服务端，各自管理自己），无远程管理 |
| 操作粒度 | 基础四项：查看 / 删除 / 清空 / 备份（不做"禁用/恢复"） |
| 分区 | 密钥管理界面区分**客户端密钥**（本机身份密钥对）与**服务端授权公钥**（部署到本机的） |
| 体检时机 | 配对建立连接的当下即执行配置体检（无连接），结果经 NDJSON 实时回传客户端 |
| 实测 | 保留：体检完成后询问"是否实测连接确认？[Y/n]"（BatchMode 真实认证） |
| 配置体检入口 | 配对流程内置 + `[4] 密钥管理` 中的 `[c]` 操作（不设独立主菜单项） |

### 新增模块

- `src/keymgr.js`：公钥解析（逐行精确对应，不受空行/注释行影响）、指纹计算（node crypto 本地实现 `SHA256:base64(sha256(base64decode(blob)))`，与 `ssh-keygen -lf` 一致）、备份（`.bak.<时间戳>`）、按行重写删除、清空、按指纹删除（`removeByFingerprints`，永不误删 keepFingerprint）、同主机旧 key 扫描（注释含 `@<clientHostname>` 且指纹不同）、管理员文件 ACL 恢复
- `src/audit.js`：11 项配置体检引擎（无连接）——公钥位置与配置一致性 / 管理员授权文件 ACL（SDDL 解析，语言无关）/ 用户文件与 .ssh 权限 / PubkeyAuthentication / AllowUsers·DenyUsers·AllowGroups·DenyGroups / sshd -t 语法 / 服务状态 / 主机密钥 / 账户启用状态（Get-LocalUser）/ 端口与防火墙配置 / 微软账户 Match 风险告警；每项 OK/WARN/SKIP/FAIL + 修复建议，ACL·防火墙·服务·主机密钥支持一键修复（`runFix`）
- `src/pair-server.js`：部署完成后自动执行体检并回传（`type:'audit'` 行）；新增 `POST /pair/cleanup`（Header 配对码，Body `{fingerprints[], keepFingerprint}`，按指纹删除、自动备份、返回 NDJSON 步骤）
- `src/pair-client.js`：透传体检行；新增 `cleanup()` 请求
- `src/cli.js`：`[4] 密钥管理`（分区界面 + c/d/k/b/g/r 操作）；客户端配对串接：部署 → 体检结论 → 旧 key 清理询问（默认 Y）→ 可选实测；本机自连同流程

### 换 key 场景闭环

客户端重新生成密钥后再次配对：新 key 幂等部署；服务器端扫描"注释主机名相同、指纹不同"的残留旧 key 并随 `done.staleKeys` 返回；客户端展示清单询问清理（默认 Y，永不误删刚部署的新 key）；删除即时生效，无需重启 sshd。
